NOTES FROM THE STUDIO

The front door now opens

By Waldas Game Studios · Development preview · not released

We built a lovely Valley Club front door and then forgot to deliver one of its hinges. The game could sign in perfectly well; the published website was missing a JavaScript module and stood there looking decorative. This update brings the hinge.

Why we changed it

Sign-in and registration deserve separate forms. Existing gardeners should not have to stare at a username box meant for new arrivals.

The publisher now follows website module dependencies automatically, so adding a new statistics helper cannot quietly strand the account page.

A successful login now stays visibly successful even if a garden or profile service needs a retry.

What changed

Website account access

  • Fixed publishing omitting a required website module, which prevented the account script and sign-in buttons from starting.
  • Sign in and Create account now have separate forms. Existing players sign in with their game email and password; usernames are requested during registration.
  • Added a clear message if account files fail to load. Profile or garden service errors no longer look like failed sign-in.
  • Website publishing now includes local JavaScript dependencies automatically and checks for missing files before uploading.

The slightly muddy bits

Confirmed the deployed garden-metrics.js returned 404 while club.html and club.js returned 200. The fix is local until the next manual website publication.

Local browser checks cover separate registration and sign-in, bad passwords, profile-service failures, missing startup files and the existing friends flow. No real player password or account was used.

This preview may change before publication.
